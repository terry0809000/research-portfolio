# Option identity in clinical annotation software

![Conceptual scientific cover](https://raw.githubusercontent.com/terry0809000/clinical-annotation-option-identity/main/assets/project-cover.png)

A valid score can still belong to the wrong option. I trace option identity through an annotation interface and its decoder, using controlled cases to make a quiet software mismatch visible.

The controlled suite and source witness separate display position from semantic identity. Endpoint detection and checkpoints answer different questions: whether a discrepancy appears, and where it first appears. Historical deployment attribution remains unresolved.

**Research direction:** Health Informatics

**Also:** Trustworthy AI

## The question

Does an annotation option retain its identity through display, saving, decoding and aggregation?

## Methods and inputs

Pinned source witnesses, synthetic semantic transport cases and stage-by-stage identity checks.

Synthetic cases and pinned public software source; original native ratings are excluded.

[Open the source and pipeline →](https://github.com/terry0809000/clinical-annotation-option-identity)

## Evidence boundary

Source incompatibility is distinct from historical deployment attribution; conditional native representations are not corrected clinical truth.

Existing study source was organized for this portfolio; scientific experiments and tests were not rerun. The AI-generated cover is conceptual raster artwork.
